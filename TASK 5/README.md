# Auto-Tagging Support Tickets Using LLMs

> **Task 5** of the DevelopersHub Corporation AI/ML Engineering Advanced Internship.
> Automatically tag free-text customer support tickets into topic categories using
> three LLM-based approaches — zero-shot, few-shot, and fine-tuned — with top-3
> tag ranking per ticket.

---

## Objective

Build a system that classifies incoming support tickets into one of ~11 topic
categories (e.g. `ORDER`, `REFUND`, `PAYMENT`, `ACCOUNT`) and returns the
**top-3 most probable tags** per ticket. Compare three modeling strategies:

1. **Zero-shot** — no training data
2. **Few-shot** — 8 examples per class
3. **Fine-tuned** — full training set

## Methodology

| Approach | Model | Training data | Why |
| --- | --- | --- | --- |
| Zero-shot | `facebook/bart-large-mnli` | None | Strong off-the-shelf NLI baseline. Treats each tag as a hypothesis. |
| Few-shot | SetFit (`all-MiniLM-L6-v2` + LR head) | 8 / class | Purpose-built for low-data text classification; outperforms in-context few-shot. |
| Fine-tuned | `distilbert-base-uncased` | Full train set | Small enough to train on a Colab T4 in ~15 min; supervised upper bound. |

All three return per-class probabilities, so the top-3 ranking is a single
`argsort` operation. All three are evaluated on the same balanced subset of
the test set for an apples-to-apples comparison.

## Dataset

[Bitext Customer Support LLM Chatbot Training Dataset](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset)
— ~27K free-text customer queries labeled across ~11 high-level categories.
Stratified 80 / 20 train-test split. A balanced 50-per-class subset is used
for the slow zero-shot evaluation.

## How to Run

### 1. Setup

```bash
python -m venv venv
venv\Scripts\activate           # Windows
# source venv/bin/activate      # macOS / Linux
pip install -r requirements.txt
```

### 2. Build the dataset

```bash
python src/load_data.py
```

### 3. Train and predict (in any order)

```bash
python src/zero_shot.py            # CPU, ~minutes
python src/few_shot_setfit.py      # CPU, ~minutes
python src/fine_tune_distilbert.py # GPU recommended -- run on Colab
```

> **Colab note for fine-tuning:** upload the `data/` folder, `pip install -r
> requirements.txt`, and run the script. The trained model gets saved under
> `models/distilbert-finetuned/` -- download that folder and drop it back
> into the local project to use it from the Streamlit app.

### 4. Evaluate

```bash
python src/evaluate.py
```

### 5. Demo

```bash
streamlit run app.py
```

## Results

Evaluated on a balanced 550-sample subset (50 per class) of the test set.
Confusion matrices are saved to `results/confusion_matrices.png`.

| Model | Top-1 Accuracy | Macro F1 | Top-3 Accuracy | N (test) |
| --- | --- | --- | --- | --- |
| Zero-Shot (BART-MNLI) | 47.27% | 0.4479 | 87.27% | 550 |
| Few-Shot (SetFit, 8/class) | **98.18%** | **0.9817** | **99.64%** | 550 |
| Fine-Tuned (DistilBERT) | **99.82%** | **0.9982** | **100.00%** | 550 |

**Fine-Tuned (DistilBERT) on full test set (4,927 samples):** Top-1 = 99.92%, Macro F1 = 0.9993, Top-3 = 99.98%

### Key observations

- **Zero-shot** reaches 47% top-1 with no training data — reasonable for 11 classes,
  but confused between semantically adjacent categories (e.g. `REFUND` vs `CANCEL`).
  Top-3 accuracy jumps to 87%, showing the correct label is almost always in the top 3.
- **Few-shot SetFit** with just **8 examples per class** leaps to 98% top-1 — a +51 point
  jump over zero-shot. This is the standout result: near fine-tuned performance at a
  fraction of the labelling cost.
- **Fine-tuned DistilBERT** is the supervised upper bound at 99.8% top-1, confirming
  that with enough labelled data the task is essentially solved.
- Top-3 accuracy is near-perfect for both trained models, which is why top-3 ranking
  is meaningful only for the zero-shot baseline.
